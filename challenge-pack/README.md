# YIT College CTF MVP — organizer pack

This pack contains 20 beginner-to-medium challenges for a team event. Every flag is static, synthetic, and has the form `YITCTF{...}`. OSINT material is offline and fictional: do not substitute real students, staff, accounts, or organizations without a written authorization and privacy review.

## Contents

- `challenge_manifest.json`: source of truth for title, category, points, flag, hint, participant file, connection, and organizer solution.
- `artifacts/`: deterministic participant material generated by `generate_artifacts.py`.
- `import_ctfd_api.py`: creates 20 CTFd challenges, static flags, and free hints with an admin API token.
- `compose.web.yml` and `web/`: four deliberately small, isolated educational Web services.

## Event settings

In **Admin Panel → Config → Users**, set account mode to **Teams** and **Team Size** to **2**. CTFd enforces this as `team_size=2`; each participant needs their own CTFd account and joins their team. CTFd cannot enforce one physical PC per person, so enforce that rule in the event brief and check-in process. Set registration, event start/end, and scoreboard visibility to your policy. Keep a non-prize organizer test team.

Total: **3,750 points** — Crypto 700, Web 800, Forensics 700, OSINT 750, Reverse 450, Misc 350.

## Build and validate artifacts

From this folder in PowerShell:

```powershell
py .\generate_artifacts.py
py -m json.tool .\challenge_manifest.json > $null
Get-ChildItem .\artifacts -Recurse -File
```

The generator only needs Python's standard library. It makes valid PNG, ZIP, gzip, PCAP, and Python-bytecode samples. Reverse challenges use Python 3.12 bytecode; publish that runtime fact in their descriptions.

## Load into CTFd

1. Start CTFd and complete initial admin setup. In **Admin Panel → Settings → Access Tokens**, create an administrator token.
2. Install the importer dependency and create the challenge metadata:

```powershell
py -m pip install -r .\requirements-import.txt
py .\import_ctfd_api.py http://127.0.0.1:8000 YOUR_ADMIN_TOKEN
```

3. Because this pack was imported into a fresh CTFd instance (C1 through M2
   have IDs 1–20), attach all participant files automatically with a fresh
   administrator token:

```powershell
py .\upload_ctfd_files_api.py http://127.0.0.1:8000 YOUR_ADMIN_TOKEN
```

   Do not upload source code, this README, the manifest, or solutions. If you prefer, you can instead upload each path printed by the importer from the CTFd challenge **Files** tab.
4. Replace `SERVER` in Web descriptions with the event LAN name/IP, for example `http://192.168.1.50:8101`.
5. From a fresh non-admin team, download every file, visit every Web endpoint, and submit all 20 answers.

If an API import partially fails, remove its partial challenges before retrying; the importer intentionally does not duplicate-detect because names may change during preparation.

## Web containers

Default binding is `127.0.0.1`, so the services remain off the LAN. For a trusted isolated event LAN, expose only their four ports and scope the corresponding Windows Firewall rule to the event subnet:

```powershell
$env:WEB_BIND = '0.0.0.0'
docker compose -f .\compose.web.yml up --build -d
docker compose -f .\compose.web.yml ps
```

For local testing omit `WEB_BIND` and use localhost ports 8101–8104. Containers use a non-root user, read-only root filesystem, temporary `/tmp`, dropped capabilities, no-new-privileges, no mounted Docker socket or host data, and no CTFd network. Stop them after testing/event:

```powershell
docker compose -f .\compose.web.yml down
Remove-Item Env:WEB_BIND -ErrorAction SilentlyContinue
```

Do not expose the upstream CTFd development ports broadly. Restrict inbound access to the event subnet; for any non-closed-lab event, put CTFd and the Web routes behind a hardened reverse proxy with TLS.

## Organizer solutions and tests

The `solution` and `flag` fields in `challenge_manifest.json` are the per-challenge answer key. Briefly: C1 Caesar -7; C2 Base64 twice; C3 Vigenere with NORTH; C4 factor 3233 then use recovered 65 as a Caesar shift. F1/F2 inspect embedded metadata, F3 inspect UDP data, F4 list ZIP contents. O1–O4 are provided fictional offline records. R1 uses strings; R2 XORs target bytes with 117. M1 gzip then Base64; M2 extracts two ZIP layers.

Representative checks:

```powershell
tar -tf .\artifacts\forensics\f4_deleted_evidence.zip
py -c "import gzip,base64;print(base64.b64decode(gzip.open('artifacts/misc/m1_strange_file.dat','rb').read()).decode())"
py -c "import zipfile; z=zipfile.ZipFile('artifacts/misc/m2_outside_the_box.zip'); z.extractall('work-m2')"
```

For Web, test in a private browser: W1 view source; W2 change `role` to `YWRtaW4=`; W3 submit username `admin' --`; W4 read `/robots.txt` then `/archive/`. Delete `work-m2` after testing.

## Deployment status and release gate

The CTFd source was inspected before this pack was added. Docker was unavailable in the current PowerShell session at pack creation, so container build, CTFd API import, file upload, and live deployment have **not** been claimed. Before announcing the event, complete the following:

- `docker compose config` succeeds for CTFd and `docker compose -f compose.web.yml config` succeeds here.
- Build/start the Web stack; complete all four Web checks; stop and restart once.
- Use a fresh two-person non-admin team to solve every challenge.
- Verify firewall scope, LAN isolation, backups, organizer access, event clock, and incident contact.
- Export CTFd after final configuration and retain the export plus this pack off the live host.
